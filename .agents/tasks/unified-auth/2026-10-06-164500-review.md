# Unified Auth Phase A & B Implementation

Implements the Partner data model (Phase A) and Docs Pool admin federation (Phase B) for the unified identity system. The implementation creates Partner and PartnerMembership tables in the platform schema, adds six admin API endpoints following existing patterns, and introduces DocsPoolVerifier for validating both Docs Pool tokens (partner developers) and Pool B tokens with moovv_admin group (admin federation).

**Watch for:** The migration script (migrate-kinetic-age.ts) uses `console.error` on failure path — acceptable since it's a one-time CLI script, not Lambda code. All Lambda handlers use Powertools logger correctly.

**Verdict**: APPROVED

---

## High-level view

The Partner model extends the existing platform schema (which already has partner_developers and partner_invite_codes) with proper B2B entity management. The migration is additive — it creates new tables and adds an optional partner_id FK to partner_developers without modifying existing data.

The admin handlers follow the established admin-list-organizations pattern exactly: verifyAdminToken, transactions with AuditLog, createSuccessEnvelope/createErrorEnvelope. All six routes are registered in serverless.yml with proper paths and methods.

DocsPoolVerifier is implemented as a standalone class (singleton pattern for Lambda warm starts) that validates tokens from Docs Pool (partner access) and Pool B with moovv_admin group check (admin access). The verifier correctly rejects Pool B tokens lacking moovv_admin group membership.

## Migration structure and constraints

The migration `20261006000001-create-partner-tables.cjs` correctly:
- Creates platform.partner with UUID PK, api_mode CHECK constraint (SDK/PORTAL/BOTH), status CHECK (ACTIVE/INACTIVE), unique constraints on sandbox/live API keys
- Creates platform.partner_membership with FK to partner, unique index on (partner_id, user_email)
- Adds nullable partner_id FK to existing partner_developers table (non-breaking for Kinetic Age)
- Uses IF NOT EXISTS / IF EXISTS for idempotency
- Proper down() migration reverses in correct order

## Model implementation

Partner.ts and PartnerMembership.ts follow sequelize-typescript patterns from existing Organization.ts:
- UUID primary keys with DataType.UUIDV4 default
- Proper @HasMany/@BelongsTo associations
- Type imports from enums.ts (not inline strings)
- Underscored column mapping enabled
- Models exported from infrastructure/index.ts and included in default export array

## Handler patterns

All six handlers match the admin-list-organizations.ts pattern:
- `verifyAdminToken(event)` at entry
- Transactions with `sequelize.transaction()` and proper commit/rollback
- AuditLog entries for mutating operations (create, update, delete)
- Zod validation for request bodies
- createErrorEnvelope with appropriate status codes (400, 401, 403, 404, 409, 422, 500)
- createSuccessEnvelope with consistent response shape
- Powertools logger (no console.log)

## DocsPoolVerifier auth federation

The verifier correctly implements the admin federation pattern from the spec:

```
Docs Pool token → partner access (accessLevel: 'partner')
Pool B token + moovv_admin group → admin access (accessLevel: 'admin')
Pool B token without moovv_admin → denied with explicit error
```

Configuration via environment variables with sensible defaults:
- COGNITO_DOCS_POOL_ID defaults to ap-south-1_fYA6SWSpX
- COGNITO_POOL_B_ID/CLIENT_IDS required for admin federation (no default)
- Mock tokens for local dev (`mock-docs-admin-token`, `mock-docs-partner-token`) only work when NODE_ENV !== 'production'

## Serverless.yml routes

All six endpoints registered:
- GET /api/admin/partners
- POST /api/admin/partners
- GET /api/admin/partners/{partnerId}
- PUT /api/admin/partners/{partnerId}
- POST /api/admin/partners/{partnerId}/members
- DELETE /api/admin/partners/{partnerId}/members/{memberId}

Environment variables for Pool B and Docs Pool added to provider.environment section.

## Kinetic Age migration

The migrate-kinetic-age.ts script is idempotent:
- Checks for existing Partner by name before creating
- Checks for existing PartnerMembership by (partnerId, userEmail) before creating
- Updates partner_developers.partner_id for all developers without a partner_id
- Transaction-wrapped with rollback on failure

The script is separate from the DB migration (manual execution required for production).

No unit tests added (per AGENTS.md: "No auto-tests. Only when requested"). The acceptance criteria verify via build + type-check commands, which pass.
